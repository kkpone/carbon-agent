# CBAM 历史回执与监测报告下载修复

## 问题与范围

监测计划生成报告需要确认时，同一个 toolCallId 跨两轮消息。旧历史逻辑先按每轮 orderNo 排序再合并，旧轮次的 autoClosed 占位可能覆盖确认后的真实成功回执。报告文件仍已生成，但刷新后报告卡片消失。运营报告共用历史处理，也纳入定向修复。

监测报告 fileId 还被通用沙箱文件解析器识别，显示数字ID并错误调用沙箱下载入口。监测报告继续由 MonitorCard 使用原有业务预览/下载接口；运营报告保留已有的专用下载处理。

## 修改

- cbamHistoryTools.ts：只识别监测计划/运营报告工具及其专用宿主，按事件 sequenceNo 合并，真实成功或失败不被自动结束和开始事件覆盖；确认后的回执保留所在消息。
- service.ts：保留原工具合并和排列，仅替换上述两类 CBAM 的结果。产品碳、组织碳、沟通表、通用沙箱工具继续使用原结果和顺序。
- AnswerMessage.tsx：已有可信监测文件回执时，不生成通用沙箱下载卡；业务报告卡继续呈现。
- scripts/test-cbam-history-download.cjs：新增历史恢复与下载分流回归。可用环境变量 CBAM_TRACE_FILE 指向本地真实日志回放，日志未复制到仓库。
