## 联调账号矩阵及待签收场景

| 测试身份 | 核心验收 |
| --- | --- |
| 未绑定团队的个人用户 | 填团队名称、报价、开通、APPLIED 后按 targetCompanyId 切换；刷新不重复开通 |
| 已绑定团队的个人用户 | 进入 boundTeamCompanyId，不再创建新团队 |
| 未开通的已有企业负责人 | 在原组织开通，保留原负责人及组织名称 |
| 有效团队管理员，有/无席位 | 管理权限与 AI 资格独立；无席位不能发起执行但可以续费/管理 |
| 到期团队管理员 | 可进入后台和续费，AI 禁用 |
| 有席位普通成员 | 仅本人对话，禁止管理路由，无管理员数据请求 |
| 无席位/停用普通成员 | 展示原因，不请求管理员摘要和财务、不跳个人充值 |
| 同账号两个标签页、多个组织 | 运行中切换、旧请求延迟、后退/刷新不串会话/文件/余额，切换不取消后端任务 |

真实联调必须覆盖：查单断网及 PAID/REVIEW 延迟；并发成员额度版本冲突；负责人保护、停用回收、重启不自动分配；CSV 部分失败/过期/恢复；重复开票；导出期间数据变化；历史表单/工具恢复和个人商城、分享、API Key、授权回归。

## 数据库与发布门禁

当前核查的后端 SQL 目录未找到完整团队版迁移来源，不能根据实体或 Mapper 认定目标库就绪。前端仓库不保留 SQL 文档，数据库迁移与执行记录由后端发布流程管理。

上线前需要后端/DB 维护者提供经过版本管理的原始迁移、执行顺序、目标环境及执行记录。必须核对订阅周期、席位/分配、额度版本、报价/订单、计费账户、导入批次、审计相关表、唯一约束及查询索引；不可从前端任务臆造 DDL。

建议执行顺序：

1. 在隔离测试库核对迁移来源、备份与兼容性；执行已审核迁移，记录目标库、版本、执行时间与核验结果。
2. 核验商品 88 元/席/月、赠送 1,000 积分、支付回调与补偿、团队初始化；联调金额以测试配置为准。
3. 用上述账号矩阵跑真实 API 与两条开通路径，记录 requestId/orderNo、预期和实际权益，真实付款由有权限人员完成。
4. 完成逐页视觉、桌面/手机及个人回归后，对测试团队/试点组织开放前端入口。
5. 观察 PAID/REVIEW 停留、初始化失败、资格拒绝、额度冲突及 SSE 恢复；回退前端版本和新增入口时保留已支付订单、成员与权益数据，继续支付回调和补偿，不破坏性回滚数据。

碳云接入、团队 SSO、手机完整后台以及计划明确排除的能力均不在本次实现范围。
